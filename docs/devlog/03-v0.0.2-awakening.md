# Transición a v0.0.2: Awakening y Nuevo Enfoque

> **La decisión de hacerlo mejor**
>
> Este proyecto, como mencioné en (`/docs/01-v0.0.1-beginning.md`), inició con otro fin. Pero a partir de repensar el proyecto, decidí refactorizarlo y 'mostrar' lo que sé hacer. Claro que no quería mostrar un proyecto 'roto' o 'incompleto', así que decidí arreglarlo y mejorarlo para que sea un proyecto estable (aunque ese es el objetivo final de la v0.1.0).

## 1. ¿Por qué 'Awakening'?

> En resumen, porque un día me desperté, recordé la existencia de este proyecto escondido, comencé a revisarlo y dije: "¿No hay muchas cosas interesantes aquí?".

El proyecto en sí no es la gran cosa, es un *skin* de Rainmeter que muestra información del sistema, pero tiene algunas características muy interesantes a nivel de desarrollo (al menos para un junior como lo era yo en ese momento). El problema es que al abrirlo, el proyecto estaba roto completamente:

- Tokens semánticos rotos: `cpu.usage` vs `cpu-usage` (y claramente muchos más).
- Conexión inestable con la API (tanto Rainmeter como el plugin). A veces el *skin* iniciaba y todo funcionaba, a veces no.
- Código muerto, CSS obsoleto, etc.
- ¿Debo seguir? En resumen: muchos problemas que solucionar.

## 2. Cambio de mentalidad (Mindset)

> **De juguete a portafolio**
> Tomé la decisión de hacerlo mejor, sacarlo estable y tener 'algo que mostrar'. No solo para mí, sino para otros; para que puedan aprender de mis errores y aciertos y yo pueda demostrar mi crecimiento.

Para que el repositorio pase de ser 'un juego personal' a 'algo que le puedo mostrar a un Senior', el código necesitaba una reestructuración. Necesitaba 'hablar por sí mismo', tener sentido y, sobre todo, funcionar bien.

- **Trazabilidad de decisiones**: Romper con el clásico estilo de "solo yo entiendo este código" y pasar a documentar mis bloqueos y las soluciones arquitectónicas. Priorizar relatar "¿Por qué?" lo hice de una forma, en vez de solo explicar "¿Qué hace?" el código.
- **Segregación y limpieza**: El repositorio contenía mucha basura e instrucciones temporales de IA, además de documentos de trazabilidad histórica. Decidí limpiarlo y contar el *porqué* real de esta reestructuración, para qué sirve y qué quiero mostrar con ella.

## 3. Refactorización Técnica y de Variables

A nivel de código, el objetivo de la v0.0.2 no era añadir características, sino limpiar y estabilizar el esqueleto:

- Se limpió gran parte de las funcionalidades extra de los sub-paneles que hoy no son parte del *roadmap* (sí, falta un `.md` de *roadmap*, lo sé jaja).
- Se estabilizó el consumo de memoria, pasando de 90MB (post Heartbeat) a apenas 60MB, luego de la limpieza de código muerto, funciones innecesarias y la purga estricta de la carga de 'estados' directamente en el DOM.
- Se corrigió la inestabilidad de la API de Rainmeter, pasando de fallos aleatorios a una conexión sólida con un manejo de errores bastante aceptable.
- Se limpiaron los *tokens* obsoletos y el CSS roto.
- Se ajustó la semántica de los atributos `data-*` utilizados tanto por los *bundles* (gráficas, alertas de estado, etc.) como por el CSS y HTML, garantizando que todo siga un patrón único y universal.

## 4. ¿Futuro del proyecto?

El futuro a partir de aquí está decidido: diseñar un *roadmap* claro desde la v0.0.3 en adelante. Tener un objetivo claro de cierre en cada versión para llevar el proyecto a una estabilidad total, dejándolo consumible y funcional tanto vía navegador (gracias al motor de `mocks`) como a través de la integración de WebView2 mediante el *fork* del plugin.

## Conclusión

El proyecto fue rediseñado a nivel conceptual, de código y de políticas de repositorio, buscando madurez en el desarrollo. El objetivo final sigue siendo experimentar con mis capacidades para entender arquitecturas complejas, pero ahora, con la estabilidad suficiente para que pueda ser consumido (y criticado constructivamente) por otros.
